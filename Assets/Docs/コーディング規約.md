# コーディング規約

このプロジェクトでスクリプトを書くときのルールです。
ルールをそろえると「どこに何が書いてあるか」がすぐわかり、ほかの人（と未来の自分）が読みやすくなります。

迷ったら、既存のスクリプト（例: `Assets/Scripts/Parts/Options/JumpParts.cs`）をお手本にしてください。

---

## 1. 文字コード・改行

| 項目 | ルール |
| --- | --- |
| 文字コード | **UTF-8**（C# スクリプト `.cs` は **UTF-8 BOM 付き**） |
| 改行コード | CRLF（Windows 標準） |
| インデント | スペース 4 つ（タブは使わない） |

- これらは [.editorconfig](../../.editorconfig) で自動設定されます。エディタの設定を変える必要はありません。
- **なぜ BOM 付き？** 日本語版 Windows の Visual Studio は、BOM が無いファイルを Shift-JIS と誤認して日本語コメントが文字化けすることがあるためです。
- 文字化けしたら：Visual Studio の「ファイル > 保存オプションの詳細設定」で「Unicode (UTF-8 シグネチャ付き)」を選んで保存し直してください。

## 2. ファイルとフォルダ

- **1 ファイルに 1 クラス**。ファイル名とクラス名は同じにする（`RCCar.cs` の中に `class RCCar`）。
  - Unity は「ファイル名 = クラス名」でないとコンポーネントとして付けられません。
- 置き場所
  - ゲームで動くスクリプト → `Assets/Scripts/` の下
  - エディタ拡張 → `Assets/Editor/` の下（ゲームのビルドには含まれません）
- すべてのクラスはプロジェクト名と同じ `namespace VantanSchoolFestival2026` の中に書く（エディタ拡張は `VantanSchoolFestival2026.EditorTools`）。

## 3. 名前の付け方

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| クラス・構造体・enum | PascalCase（単語の頭を大文字） | `RCCar`, `GameState` |
| メソッド | PascalCase | `Respawn()`, `ReachGoal()` |
| プロパティ | PascalCase | `IsGrounded`, `MaxSpeed` |
| private フィールド | `_` + camelCase | `_jumpPower`, `_car` |
| ローカル変数・引数 | camelCase | `targetSpeed`, `deltaTime` |
| 定数 (`const`) | PascalCase | `PlayerPrefabPath` |
| bool | `Is` / `Has` / `Can` で始める | `IsBoosting`, `CanDrive` |

- 名前は **英語** で、略さずに書く（`spd` ではなく `speed`）。
- 部品の種類がわかる語尾をつける
  - 駆動方式 → `○○Drive`、追加パーツ → `○○Parts`

## 4. Inspector に出す値（`[SerializeField]`）

```csharp
[Header("ジャンプ")]
[Tooltip("ジャンプの強さ（上向きに加える速度 メートル/秒）。")]
[Range(1f, 20f)]
[SerializeField] private float _jumpPower = 6f;
```

- Inspector に出したい値は **`public` にせず `[SerializeField] private`** にする。
  - `public` にすると、ほかのスクリプトから勝手に書き換えられてしまうため。
- **`[SerializeField]` には必ず `[Tooltip("…")]` を付ける。**（必須）
  - Inspector で項目にマウスを乗せると説明が表示されます。
  - 単位（メートル、秒、度）と「大きくするとどうなるか」を書くと親切です。
- 数値には、意味のある範囲で `[Range(最小, 最大)]` を付ける。
- 関係のある項目は `[Header("見出し")]` でまとめる。
- ほかのスクリプトから読ませたい値は、プロパティで「読み取り専用」にする。

```csharp
public bool IsGrounded { get; private set; }   // 外からは読むだけ
```

## 5. コンポーネントの属性

| 属性 | 意味 | ルール |
| --- | --- | --- |
| `[AddComponentMenu("VantanSchoolFestival2026/分類/名前 (クラス名)")]` | Add Component メニューでの表示場所 | **すべてのコンポーネントに必須** |
| `[ComponentSummary("概要", "使い方", "関連")]` | Inspector 上部のプルダウン「このコンポーネントについて」に表示する説明 | **すべてのコンポーネントに必須** |
| `[RequireComponent(typeof(○○))]` | 必要な部品を自動で追加 | 必要な部品があれば付ける |
| `[DisallowMultipleComponent]` | 同じ部品を 2 つ付けられなくする | 2 つあると困る部品に付ける |

`AddComponentMenu` の分類は次の 6 つです。

| 分類 | 例 |
| --- | --- |
| `VantanSchoolFestival2026/Core/` | RCCar, GameManager |
| `VantanSchoolFestival2026/入力/` | PlayerCarInput, ActionMapSwitcher |
| `VantanSchoolFestival2026/UI/` | HudView, HudPresenter, ControlsHintView, ControlsHintPresenter |
| `VantanSchoolFestival2026/駆動方式/` | ArcadeDrive, DriftDrive, TankDrive |
| `VantanSchoolFestival2026/追加パーツ/` | JumpParts, BoostParts, ColorParts |
| `VantanSchoolFestival2026/ステージ/` | Goal, SpeedPad, KillZone |

## 6. コメント

- ファイルの先頭に **「役割」「しくみ」「使い方」** を書いたヘッダーコメントを付ける。
- クラス・public メソッド・プロパティには **XML ドキュメントコメント** を付ける。

```csharp
/// <summary>最後に設定されたリスポーン地点へ車を戻す。</summary>
public void Respawn() { ... }
```

- 処理の中には「**何をしているか**」より「**なぜそうするか**」を書く。
  - ✖ `// 速度を 0 にする`
  - ◎ `// 勢いを止める（止めないと、戻った瞬間に飛んでいってしまう）`
- 初めて出てくる Unity の機能には、短い説明を添える（例: `// Lerp … 少しずつ近づける`）。

## 7. Unity ならではの書き方

- `Rigidbody` を動かす処理は `FixedUpdate` に、それ以外は `Update` に書く。
- カメラは自作せず **Cinemachine** を使う。画面効果は **Volume（ポストプロセス）** を使う。
  Unity 公式の機能で実現できるものは、自分で作らずにそれを使う。
- 自分の準備は `Awake`、ほかのオブジェクトを探すのは `Start` で行う。
- イベントの登録 `+=` は `OnEnable`、解除 `-=` は `OnDisable` で行う。
- `GetComponent` は重い処理なので、`Awake` で 1 回だけ呼んで変数に入れておく。
- 毎フレーム `FindFirstObjectByType` を呼ばない（重い）。

## 8. 書き方（スタイル）

- 波かっこ `{ }` は **次の行** に書く（Allman スタイル）。
- `if` の中身が 1 行でも、基本は `{ }` を付ける（短い `return` などは 1 行で OK）。
- `this.` は付けない。
- `var` は右辺で型がはっきりわかるときだけ使う。

## 9. UI は MVP で作る

画面（UI）のスクリプトは、3 つの役割に分けて書きます。

| 役割 | 何をするか | 例 |
| --- | --- | --- |
| **Model** | データとルール。画面のことは知らない | `GameManager`, `RCCar`, `ControlsHintModel` |
| **View** | 見た目。言われた値を表示するだけ。ゲームのことは知らない | `HudView`, `ControlsHintView` |
| **Presenter** | Model を読んで View に表示させる「つなぎ役」 | `HudPresenter`, `ControlsHintPresenter` |

- View には `if (ゲームの状態 == …)` のような判断を書かない（それは Presenter の仕事）。
- 見た目を作り直すときは View とプレハブだけを触れば済むようにする。

## 10. 入力と車を分ける

- 車（`RCCar`）は入力デバイスを知らない。`SetDriveInput()` / `SetBoost()` / `RequestJump()` / `RequestRespawn()` で命令を受け取るだけ。
- キーボード・ゲームパッドの入力は `PlayerController` の `PlayerCarInput` が受け取り、車に命令を送る。
- 新しい操作方法（AI・リプレイなど）を作るときは、`PlayerCarInput` と同じように車へ命令を送るコンポーネントを作る。
